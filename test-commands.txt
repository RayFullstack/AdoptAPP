============================================
  ADOPTAPP - COMANDOS DE PRUEBA (curl)
============================================
Ejecutar desde terminal (PowerShell, Git Bash o WSL).
Reemplazar {id} con IDs reales devueltos por los GET.

============================================
  PERFIL: PostgreSQL (todos los servicios)
============================================
Requisitos: PostgreSQL corriendo en localhost:5432 con las bases de datos creadas.
Variables de entorno necesarias: DB_USER, DB_PASSWORD

Servicios y puertos:
  user-service:       8081  (/user-app)
  pet-service:        8082  (/pet-app)
  adoption-service:   8083  (/adoption-app)
  notification-svc:   8084  (/notification-app)
  health-service:     8085  (/health-app)
  followup-service:   8086  (/followup-app)
  staff-service:      8091  (/staff-app)
  donation-service:   8090  (/donation-app)
  supply-service:     8092  (/supply-app)
  shelter-service:    8095  (/shelter-app)

============================================
  1. USER-SERVICE (puerto 8081)
============================================
Base: http://localhost:8081/user-app

--- GET ---
curl http://localhost:8081/user-app/users
curl "http://localhost:8081/user-app/users?status=ACTIVE"
curl http://localhost:8081/user-app/users/by-id/{id}
curl http://localhost:8081/user-app/users/by-email/{email}
curl http://localhost:8081/user-app/users/by-email/{email}/auth
curl http://localhost:8081/user-app/users/by-id/{id}/history

--- POST ---
curl -X POST http://localhost:8081/user-app/users ^
  -H "Content-Type: application/json" ^
  -d "{\"username\":\"jdoe\",\"name\":\"John\",\"surname\":\"Doe\",\"email\":\"john@example.com\",\"password\":\"secret123\",\"phone\":\"+123456789\",\"country\":\"USA\",\"city\":\"New York\",\"street\":\"5th Ave\",\"homeNumber\":\"123\",\"postalCode\":\"10001\",\"type\":\"HOME\",\"status\":\"ACTIVE\",\"role\":\"ADOPTER\",\"active\":true}"

--- PUT ---
curl -X PUT http://localhost:8081/user-app/users/by-id/{id} ^
  -H "Content-Type: application/json" ^
  -d "{\"username\":\"jdoe_updated\",\"name\":\"John\",\"surname\":\"Doe\",\"email\":\"john@example.com\",\"password\":\"newpass123\",\"phone\":\"+123456789\",\"country\":\"USA\",\"city\":\"Los Angeles\",\"street\":\"Main St\",\"homeNumber\":\"456\",\"postalCode\":\"90001\",\"type\":\"HOME\",\"status\":\"ACTIVE\",\"role\":\"ADOPTER\",\"active\":true}"

--- DELETE ---
curl -X DELETE http://localhost:8081/user-app/users/by-id/{id}

============================================
  PERFIL: H2 (servicios con profile h2)
============================================
Requisitos: Ninguno (H2 es embebido, no necesita PostgreSQL).
Los servicios con profile h2 usan base de datos en memoria.

Servicios con profile h2 disponibles:
  user-service:       8081  (/user-app)       --spring.profiles.active=h2
  pet-service:        8082  (/pet-app)        --spring.profiles.active=h2
  adoption-service:   8083  (/adoption-app)   --spring.profiles.active=h2
  notification-svc:   8084  (/notification-app) --spring.profiles.active=h2
  health-service:     8085  (/health-app)     --spring.profiles.active=h2
  followup-service:   8086  (/followup-app)   --spring.profiles.active=h2
  staff-service:      8091  (/staff-app)      --spring.profiles.active=h2
  donation-service:   8090  (/donation-app)   --spring.profiles.active=h2
  supply-service:     8092  (/supply-app)     --spring.profiles.active=h2
  shelter-service:    8095  (/shelter-app)    --spring.profiles.active=h2

Para iniciar un servicio con profile h2 desde IntelliJ:
  - Editar Run Configuration
  - En "VM options" o "Program arguments": --spring.profiles.active=h2

O desde linea de comando (ejemplo user-service):
  java -jar user-service/target/user-service-0.0.1-SNAPSHOT.jar --spring.profiles.active=h2

Los mismos comandos curl de arriba aplican para el perfil H2.
La diferencia es que los datos se pierden al reiniciar el servicio.

============================================
  NOTAS IMPORTANTES
============================================
1. Algunos endpoints requieren autenticacion. Si el servicio tiene Spring Security
   habilitado, agregar credenciales con -u user:pass o token Bearer.

2. Los campos amount en donation-service ahora usan BigDecimal (formato numerico JSON).

3. Para PowerShell usar ` en lugar de \ para continuacion de linea.

4. Para Git Bash/WSL usar \ para continuacion de linea y comillas simples '.

5. Reemplazar {id}, {email}, {shelterId} con valores reales obtenidos de los GET.

6. Si un servicio depende de otro (ej: donation necesita user y shelter),
   crear primero los recursos dependientes.
